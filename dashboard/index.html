TokWiz Documentation & Technical Reference

Plain-English guide to how TokWiz saves tokens, forecasts costs, and calibrates predictions.

Contents

1. How TokWiz Saves Tokens (Plain English)

AI coding agents normally waste 5x–20x more tokens than needed because they wander through repositories with repeated searches, dump huge files into chat history, and re-read unchanged files. TokWiz stops that waste at the tool layer—without ever stripping code correctness or security details:

  • Map First, Don't Wander (tokwiz graph & slice): Instead of running 6–10 grep/find commands, TokWiz queries a local map of every function and its callers (.tokwiz/graph.db) and returns only the exact lines needed.
  • Table of Contents Before Full Files (tokwiz skeleton): If the AI tries to read a large code file (>300 lines) or config/data file (>150 lines of JSON/YAML/TOML/SQL), TokWiz blocks the full dump and returns a compact outline with exact line numbers.
  • No Duplicate Reads (SHA-1 Read Cache): If the AI tries to re-read an unchanged file range already in context, TokWiz intercepts it with a 15-token [TokWiz Cache Hit] reminder.
  • Skip Junk & Noise (output-filter & tokwiz test): Blocks lockfiles (package-lock.json, Cargo.lock) and node_modules/, strips test pass spam, and runs only tests affected by your git diff.
  • Receipt-Backed Accounting: Every saved token shown on this dashboard is backed by a concrete tool receipt. If the AI reads a full file anyway, 0 tokens are credited.

2. How Pre-Prompt Forecasting & Prediction Work

Before your AI model spends a single token, TokWiz predicts the full workflow cost in <50ms and 0 API tokens by combining prompt intent with your codebase graph:

Step 1 — Blast Radius from the Code Graph

TokWiz extracts symbol names or keywords from your prompt and queries .tokwiz/graph.db to count how many files, callers, and lines of code sit in the task's blast radius.

Step 2 — Complexity Classification (Profiles A – E)

ProfileTask TypeEst. StepsTypical Behavior
ADirect Q&A / Explanation0 – 1Answers from graph or 1 targeted read
BTargeted Single-File Edit2 – 4Skeleton + ranged read + edit + test
CMulti-File Feature / Refactor5 – 10Graph slice + cross-file edits + test verification
DDeep Debugging / Test Triage6 – 14Filtered test logs + iterative trace & fix
ERepo-Wide Architecture8 – 18Broad exploration + subagent isolation

Step 3 — Cross-Provider Pricing & Cache Discounts

Using references/pricing-matrix.json, TokWiz calculates both uncached cost and realistic cached cost—modeling 90% prompt-cache discounts for Claude and 75% discounts for OpenAI Codex and Gemini.

3. Mathematical Formulas Explained in Plain English

A. Multi-Step Workflow Token Forecast

Counting only the words in your prompt fails because AI agents re-send the growing conversation on every tool call—like a snowball rolling downhill:

Total Forecast = T_context + T_prompt + Σ (i = 1..N_steps) [ T_context_i + T_tool_in_i + T_tool_out_i ] + T_reasoning + T_output
In plain English: Starting context + your prompt + (each tool call adds to the chat history and gets re-read on every remaining step) + AI thinking + final answer. Cutting 5 unnecessary tool steps shrinks every subsequent step!

B. Residual Error / Cost Delta (ΔC) & Forecast Accuracy (APE % / MAPE)

Residual Error (ΔC $) = Real Cost − Forecast Cost
APE % = ( |Real Cost − Forecast Cost| / Real Cost ) × 100%
MAPE = Average of APE % across all completed turns
In plain English: Residual Error (ΔC) is simply the leftover dollar gap between what TokWiz predicted and what you were actually billed. Positive (+$0.02, pink bar) means the turn cost more than forecasted; negative (-$0.02, purple bar) means it cost less than forecasted. Lower MAPE means tighter predictions (TokWiz targets ≤ 20%).

C. Self-Calibrating EMA Weight Update (scripts/calibration.py)

Every codebase is different. After each turn finishes, TokWiz compares Forecast vs. Real and nudges its future multipliers using an Exponential Moving Average (EMA) with learning rate α = 0.35:

W_new = (1 − 0.35) × W_old + 0.35 × (Observed / Forecast)
In plain English: TokWiz blends 65% of what it already learned about your repo with 35% from the latest turn. Within 3–5 prompts, forecasts automatically adapt to your project's style without overreacting to a single weird prompt.

D. Personalized PageRank Graph Slicing (α = 0.85)

Rank(node) = (1 − 0.85) × Seed(node) + 0.85 × Σ [ Rank(neighbor) / OutDegree(neighbor) ]
In plain English: Think of it like Google's PageRank starting from the symbol you asked about—walking 15 hops along CALLS and IMPORTS edges to rank the most tightly connected callers and callees that fit inside your --max-tokens budget.

4. Codebase Graph & Deterministic Guardrails

  • Polyglot SQLite Graph (.tokwiz/graph.db): Indexes Python, TypeScript/JS/TSX, Go, Rust, Java, C/C++, C#, and Ruby with WAL journaling. Incremental updates fingerprint files by (mtime, size, sha1) and skip unchanged files in <5ms.
  • PreToolUse Hook (hooks/pre-tool-guard.py): Runs before read_file or shell commands with a strict <200ms fail-open SLA—if anything ever errors, it safely allows the tool so your IDE never hangs.
  • Native MCP Server (tokwiz mcp): Exposes graph, slice, skeleton, predict, and stats tools over stdio JSON-RPC in <5ms with zero shell approval prompts.

6. Statuses, Variance Tags & Source Badges

Every row in the Prompt Forecast & Cost Reconciliation Audit Log shows a status badge explaining whether real usage matched the pre-prompt prediction, and a source badge showing where the usage numbers came from.

Audit Log Status / Variance Tags

Status BadgeWhat It Means (Plain English)Exact Trigger Rule
ON_TARGET Real token usage stayed within expected bounds. None of the drift tags below were triggered.
PENDING_FORECAST A pre-prompt forecast was created, and TokWiz is waiting for the turn to finish and reconcile actual billing. Entry exists in active-forecast.json / forecasts.jsonl without a final post-turn reconciliation yet.
EXTRA_TOOL_LOOPS The agent took noticeably more search/edit steps than planned. real_steps > forecast_steps + 2, ≥ 1.4× forecast steps, and real_total > 1.15× forecast.
CACHE_MISS_DRIFT Prompt caching dropped, so repeated context was billed at full uncached input rates instead of discounted cache reads. input_tokens > 500 and cached_input_tokens / input_tokens < 0.45.
REASONING_SPIKE The model spent significantly more thinking/reasoning tokens than predicted. real_reasoning > 1.5× forecast_reasoning (+200 min) and real_total > 1.15× forecast.
UNBOUNDED_TOOL_OUTPUT Tool outputs (or cumulative multi-turn context reads) were much larger than the pre-prompt estimate. real_tool_tokens > 1.5× forecast_tool (+300 min) and real_total > 1.15× forecast.

Telemetry Source Badges

Source BadgeWhere the Numbers Came From
API_EXACT Exact token counts returned directly by the model/CLI API response (includes uncached input, cache reads, cache writes, and output).

7. Dashboard & Table Glossary

Tokens (Input vs. Output) Small chunks of text (~4 characters each) billed by AI providers for reading files/prompts (Input) and generating replies (Output).
KV-Cache / Cache-Read Tokens Repeated prefix context (like system instructions) served from provider memory at a 75%–90% discount.
Source (TRANSCRIPT / HOOK / CLI) Where the turn was recorded: TRANSCRIPT = auto-synced from Antigravity, Claude Code, or Codex logs; HOOK = captured live.
Saved Tok (Receipts) Verified tokens saved via GRAPH_QUERY, SKELETON_AND_RANGE, RANGED_READ, OUTPUT_FILTER, or SESSION_READ_CACHE_HIT.
Variance Tags (Status) Why Real cost differed from Forecast: ON_TARGET, EXTRA_TOOL_LOOPS, CACHE_MISS_DRIFT, REASONING_SPIKE, or UNBOUNDED_TOOL_OUTPUT.
Residual Error (ΔC $) The dollar difference between actual billed cost and the pre-prompt forecast (Real $ − Forecast $). Positive = cost more than predicted; negative = cost less than predicted.
Baseline vs. TokWiz (A/B Proof) Side-by-side run of identical prompts in a plain repo vs. a TokWiz repo, verifying 100% test pass in both.
